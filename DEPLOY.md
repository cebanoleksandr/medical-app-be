# Деплой (бесплатно)

| Что | Где | Бесплатный лимит |
|---|---|---|
| API (NestJS) | Render, web service | 512 МБ RAM, засыпает после 15 мин простоя |
| Presidio | Render, web service | то же |
| PostgreSQL | [Neon](https://neon.tech) | 0.5 ГБ |
| Почта | [Resend](https://resend.com) | 3000 писем в месяц, 100 в день |
| Фронтенд | Vercel (или Netlify) | — |

Почему так:
- **Почта через Resend.** Бесплатные Render и Railway блокируют исходящий SMTP, а Resend отправляет письма по HTTPS. Нужен свой домен (см. шаг 2). Brevo тоже поддерживается (`MAIL_PROVIDER=brevo`), но требует подтверждения телефона, а SMS на украинские номера доходят ненадёжно.
- **База на Neon.** Бесплатный Postgres на Render удаляется через 30 дней.
- **Регион.** Всё в EU (Frankfurt): это ближе к Украине и проще с точки зрения GDPR.

## 1. Neon

1. Создайте проект. Регион: **AWS Europe Central (Frankfurt)**.
2. Скопируйте connection string: `postgresql://…@….neon.tech/neondb?sslmode=require`. Это будет `DATABASE_URL`.

Таблицы создавать не нужно: API применит миграции при первом запуске.

## 2. Resend

1. Зарегистрируйтесь на [resend.com](https://resend.com).
2. **API Keys → Create API Key.** Permission: **Sending access**. Ключ начинается с `re_` и показывается один раз. Это будет `RESEND_API_KEY`.
3. **Domains → Add Domain.** Укажите домен, лучше поддомен, например `mail.your-domain.com`. Регион: **eu-west-1 (Ireland)**. Resend покажет DNS-записи: MX и TXT для SPF, TXT для DKIM. Добавьте их у регистратора домена и нажмите **Verify**. Обычно проверка занимает от нескольких минут до часа.
4. `MAIL_FROM_EMAIL` — любой адрес на этом домене, например `noreply@mail.your-domain.com`. Сам почтовый ящик создавать не нужно.

> **Без своего домена** можно отправлять с `onboarding@resend.dev`, но письма будут доходить **только на email, с которым вы зарегистрировались в Resend**. Этого хватит, чтобы проверить деплой самому, но другие пользователи войти не смогут. Если домена нет, подойдёт любой недорогой: .xyz, .site и т.п. обычно стоят $1–3 в первый год.

## 3. Render

1. Запушьте этот репозиторий на GitHub.
2. Render → **New → Blueprint** → выберите репозиторий. Render прочитает [render.yaml](render.yaml) и создаст два сервиса: `deid-presidio` и `deid-api`.
   - Секреты `JWT_ACCESS_SECRET`, `PSEUDONYM_SECRET`, `SOURCE_ENCRYPTION_KEY` и общий `PRESIDIO_API_KEY` сгенерируются автоматически.
3. Render попросит заполнить переменные с `sync: false`:

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | строка подключения из Neon |
   | `RESEND_API_KEY` | ключ из Resend (`re_…`) |
   | `MAIL_FROM_EMAIL` | адрес на подтверждённом домене (или `onboarding@resend.dev` для теста) |
   | `CONTACT_TO_EMAIL` | почта команды, куда приходят сообщения из формы на лендинге. Без своего домена в Resend — только email вашего аккаунта Resend |
   | `PRESIDIO_URL` | `https://deid-presidio.onrender.com` — точный адрес видно на странице сервиса; если имя занято, Render добавит суффикс |
   | `APP_URL` | адрес фронтенда, например `https://deid-studio.vercel.app`, без `/` в конце |
   | `APP_LINK_BASE` | только если фронтенд открывается не с корня домена. GitHub Pages с hash-роутером: `https://<user>.github.io/<repo>/#` — тогда ссылка в письме будет `…/<repo>/#/auth/verify?token=…`. Иначе оставьте пустым |

   Если адреса Presidio или фронтенда ещё неизвестны, введите заглушку, а после первого деплоя исправьте её в **deid-api → Environment**. Сохранение перезапустит сервис.
4. Дождитесь сборки. Первая сборка Presidio занимает около 5 минут: скачиваются модели spaCy.

**Проверка:**

```bash
curl https://deid-api.onrender.com/api/health        # {"status":"ok"}
curl https://deid-presidio.onrender.com/health       # {"status":"ok","languages":["en","uk"]}
```

## 4. Фронтенд

API ставит refresh-токен в `httpOnly` cookie. Проще и надёжнее всего, чтобы браузер видел фронтенд и API **на одном домене**. Для этого фронтенд проксирует `/api/*` на Render. На Vercel `vercel.json` в корне фронтенда будет таким:

```json
{
  "rewrites": [
    { "source": "/api/:path*", "destination": "https://deid-api.onrender.com/api/:path*" },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

После этого фронтенд обращается к API по относительному пути `/api/...`, а `COOKIE_SAMESITE=lax` работает без изменений.

<details>
<summary>Если проксировать нельзя (фронтенд и API на разных доменах)</summary>

Задайте `COOKIE_SAMESITE=none` и вызывайте API по полному адресу с `credentials: 'include'`. Минус: Safari и браузеры с блокировкой сторонних cookie могут не сохранить refresh-cookie, и тогда пользователя будет разлогинивать через 15 минут.
</details>

## Особенности бесплатного тарифа

- **Засыпание.** Сервисы засыпают через 15 минут без запросов. Первый запрос после простоя ждёт пробуждения API: примерно до минуты.
  - Presidio будится автоматически при старте API и при открытии мастеров (`GET /api/analyses/options`, `GET /api/synthetic/options`), поэтому к моменту анализа он обычно уже готов.
  - На фронтенде стоит показать индикатор «Сервер просыпается…» и повторить запрос после таймаута.
- **Автоматические задачи.** Очистка просроченных источников синтетики и старого аудита работает, пока сервис не спит, и запускается при каждом старте.
- **Память.**
  - API: около 80 МБ в простое, около 280 МБ на пике (экспорт XLSX на 100 000 записей).
  - Presidio: около 310 МБ.

  Оба укладываются в 512 МБ.

## Смена секретов

| Секрет | Что произойдёт |
|---|---|
| `JWT_ACCESS_SECRET` | всем пользователям придётся войти заново через 15 минут |
| `PRESIDIO_API_KEY` | менять в группе `deid-shared`, тогда он обновится у обоих сервисов сразу |
| `PSEUDONYM_SECRET` | в режиме Pseudonymize изменятся фейковые значения у открытых анализов |
| `SOURCE_ENCRYPTION_KEY` | загруженные источники синтетики перестанут читаться; они и так живут не дольше `SYNTH_DATASET_TTL_MINUTES` |

## Чек-лист после деплоя

- [ ] `/api/health` отвечает `ok`, `/api/docs` отвечает 404 (Swagger в production выключен).
- [ ] Письмо со ссылкой приходит, и по ссылке вход работает.
- [ ] Анализ текста проходит на английском и украинском.
- [ ] Генерация датасета и скачивание CSV / XLSX работают.
- [ ] В логах Render (**deid-api → Logs**) нет текста документов и email.
